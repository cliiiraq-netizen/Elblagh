# مطابقة صفحة الطلب مع ewsali.com/order — جدول الفروقات

تاريخ الفحص: 2026-11-26. الأجهزة: iPhone 13 (390×664) و1440×900، فاتح وداكن.
**طريقة الفحص:** نسخنا كل CSS عندهم (keyframes وtransitions والقياسات)، وسجّلنا تسلسل الهيرو كل 30ms، وأخذنا لقطات بنفس التوقيت للصفحتين (البداية كل 300ms لمدة 6 ثواني، وكل تفاعل بـ 4–13 لقطة)، وقارنّا قياسات كل عنصر (الموقع والحجم والخط والوزن وارتفاع السطر واللون والحواف والـ padding).
**الأمان:** كل طلب غير GET/HEAD كان محجوب، وما ضغطنا «تأكيد الطلب» وفيه بيانات، وما رفعنا أي ملف.

الملف اللي تعدّل: `tools/order.template.html` بس (بعدها شغّلنا `tools/build_order.py`).
الحالة: ✅ صار مطابق · 🟡 فرق مقصود (هوية إبلاغ أو ميزة عندنا) · ⚪ فرق صغير ومقبول

## الاختبارات
`order-test.js`: **33/33**، بدون أخطاء بالـ console. أربع تعديلات بالاختبار بسبب السلوك المطابق (الشرح مكتوب داخل الملف):
1. «tap shows urgent capsule»: صار يفحص بعد 3.1s (الكبسولة تنزل بـ 2.9s، مثل ewsali).
2. «alert text rotates»: صار يضغط مرة ثانية بعد ما تخلص الدورة (6.9s بدل 4.9s)، لأن الرسالة الجديدة تطلع بس بعد نهاية الدورة.
3. «sticky bar shows»: انتقل لبعد اختيار الباقة، والفحص صار `!#bar.hid` (الشريط مخفي لحد ما تختار، مثل ewsali).
4. انشالت ضغطة `[data-plan="basic"] summary` (كانت بس للقطة شاشة، مو فحص)، لأن قائمة «كل المزايا» ما موجودة عند ewsali.
